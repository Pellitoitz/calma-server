# SimForge 1.1 — Roadmap (alcance BALANCED, pendiente de aprobación)

Cada etapa es pequeña, se prueba de forma independiente, es reversible y está acotada. Cada etapa termina en un
**checkpoint y STOP**: la siguiente no empieza sin aprobación.

**Contratos comunes a todas las etapas:**

- FREEZE intacto y 01–05 idénticos;
- `ENGINE_VERSION` 0.9.0;
- sin IA ni optimización;
- sin migraciones salvo decisión explícita;
- pytest completo + ruff + `check_release.py` (adaptado a la rama) en cada checkpoint.

## 1.1-A — Comparación y escenarios (C08 + C07 + C16)

| | |
|---|---|
| Alcance | servicio de comparación física run↔run (deltas por KPI, emparejada sólo con evidencia de CRN, avisos de comparabilidad: horizonte, warm-up, réplicas, demanda, mix, calendarios); CLI `project compare-runs` y `project experiment`; UI con el flujo baseline → clonar → modificar parámetros → aprobar → ejecutar → comparar |
| No objetivos | ranking, «mejor escenario», optimización; guardar comparaciones en la BD |
| Contratos | `delta = alt − base`; emparejada ⇔ mismas semillas, réplicas y horizonte; clonar conserva el linaje (versión padre, escenario, baseline); la aprobación sigue las reglas de 1.0 |
| Tests | deltas exactos en casos deterministas; IC emparejado frente a no emparejado; avisos; linaje de los clones; smoke de CLI y UI; test de términos (sin recomendación) |

| Documentación | `docs/user/07_experiments.md` y una guía nueva de escenarios |

**Decisiones de alcance tomadas en 1.1-A:**

- Una ventana medida distinta (horizonte o warm-up) es HARD_INCOMPATIBILITY: no se normaliza.
- Los deltas de experimento son frente a un escenario del propio experimento. C09 completo (frente al run baseline del
  proyecto) sigue en 1.2.
- C16 = paridad de la CLI según este roadmap. C17 (productividad) queda en 1.1-E.

**Limitaciones:** ver la guía 16, sección «Limitaciones».

## 1.1-B — Construcción del modelo sin YAML (C01 + C02 + C03)

| | |
|---|---|
| Alcance | en la pestaña Model: añadir o quitar nodos desde la biblioteca, conectar y desconectar, editar distribuciones (familia, parámetros, unidad, truncamiento) y transporte; cada cambio crea una versión verificada |
| No objetivos | editores de productos/setups y de mantenimiento (1.2); arrastrar y soltar; un editor gráfico libre |
| Contratos | modelo construido en la UI = mismo hash que el YAML equivalente; ningún default silencioso (MISSING sigue visible); campos desconocidos = error |
| Tests | construir 01 y el golden desde cero en la UI (AppTest) y comparar hashes; round-trip de distribuciones; rechazo de valores inválidos |
| Regresiones | 01–05, verificador congelado intacto |
| Documentación | `docs/user/03_building_a_model.md`, tutorial |
| Checkpoint | **STOP** |

## 1.1-C — Results workbench y diagnóstico factual (C10 + C11 + C13)

| | |
|---|---|
| Alcance | vista consolidada de KPIs con IC; distribuciones por réplica; tablas de recursos y nodos; colas, bloqueo y hambre; setup, mantenimiento y calendario cuando existan; rankings top-N factuales con evidencia; KPIs superpuestos al grafo |
| No objetivos | interpretación automática, recomendaciones, IA |
| Contratos | cada número sale de KPIs guardados (sin recalcular la simulación); las frases describen («el nodo X tuvo un 92 % de utilización») y nunca prescriben |
| Tests | valores = KPIs guardados; test de términos prohibidos; AppTest |
| Regresiones | sin cambios en los KPIs |
| Checkpoint | **STOP** |

## 1.1-E — Supuestos económicos, productividad y biblioteca (C06 + C17 + C15)

| | |
|---|---|
| Alcance | editor de supuestos económicos en la UI (tarifas, bases, procedencia, CAPEX, anualización) que crea una versión y evalúa sin DES; panel de productividad (tiempo hasta el primer run válido, hasta una comparación, bucles); tests de comportamiento para los componentes `draft` **sin modificar los ficheros FREEZE de la biblioteca** |
