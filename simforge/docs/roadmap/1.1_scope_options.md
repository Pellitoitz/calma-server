# SimForge 1.1 — Opciones de alcance

Las tres opciones comparten estos principios:

- el motor 0.9 es el **kernel estable** y no se modifica;
- todo se construye en las capas de aplicación, UI, CLI e informes sobre los contratos existentes;
- no hay IA ni optimización;
- FREEZE intacto y 01–05 idénticos;
- sin migraciones salvo decisión explícita.

## MINIMAL 1.1: «comparar sin rodeos»

| | |
|---|---|
| Incluye | C08 comparación física run↔run (servicio, CLI, UI) · C07 flujo de escenarios en la UI · C02 editor de distribuciones · C12 (sólo el informe de comparación) |
| Beneficio | ataca el cuello de botella de **análisis**: comparar alternativas de forma trazable y emparejada, sin economics y sin la CLI |
| Complejidad | LOW-MEDIUM |
| Riesgo | LOW: sólo lectura de resultados, más versiones y escenarios existentes |
| Orden | C08 → C07 → C12-comparación → C02 |
| Diferido | constructor estructural, editores de extensiones, results workbench, diagnóstico ampliado |

## BALANCED 1.1: «workbench de ingeniería»

| | |
|---|---|
| Incluye | MINIMAL + C01 constructor estructural + C03 transporte + C06 editor de supuestos económicos + C10 results workbench + C11 diagnóstico factual + C13 KPIs sobre el grafo + C12 completo (secciones de productos/setups, mantenimiento y datos) + C16 paridad de la CLI + C17 productividad visible + C15 tests de la biblioteca |
| Beneficio | ataca los **cuatro** cuellos de botella: construir sin YAML lo más frecuente, analizar, comparar e informar. Mide la ganancia (C17) |
| Complejidad | MEDIUM: el mayor bloque es C01 |
| Riesgo | LOW-MEDIUM: C01 produce modelos, mitigado con tests de equivalencia de hash (UI = YAML) y la verificación existente |
| Orden | etapas A–E (ver `1.1_roadmap.md`) |
| Diferido | C04 productos/setups, C05 mantenimiento, C09, C14, C18, C19, C20 → 1.2 |

## AMBITIOUS 1.1: «sin YAML nunca»

| | |
|---|---|
| Incluye | BALANCED + C04 editor de productos/setups + C05 editor de mantenimiento + C09 deltas de experimento + C14 plantillas + C18 espacio de validación + C19 enlace con datasets + C20 idioma |
| Beneficio | máxima cobertura sin YAML |
| Complejidad | HIGH: los editores de 0.7 y 0.8 tienen semántica rica (matrices, familias, estado inicial, relojes, PM) |
| Riesgo | MEDIUM: más superficie que puede generar modelos sutilmente distintos; la ventana de estabilización de RC1 aún no se ha ejecutado, así que el uso real no ha informado esos editores |
| Orden | BALANCED A–E → F (productos/setups) → G (mantenimiento) → H (resto) |
| Diferido | IA, interoperabilidad, extensiones de dominio |
