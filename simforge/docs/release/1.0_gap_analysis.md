# SimForge 1.0 — Release gap analysis

Estado de partida: commit `26cf484`, 652 tests, ruff limpio, FREEZE intacto, regresión 01–05 exacta.

Método: auditar el flujo de punta a punta con ejecuciones reales (procesos separados, instalación limpia, AppTest de la
UI). Cada hallazgo se clasifica como **bug** (con un test que falla antes del arreglo), **barrera de uso**,
**documentación** o **diferido**.

## A. Bugs reales encontrados y corregidos

Todos tienen un test en `tests/test_release_readiness.py` o en `tests/test_release_smoke.py` que falla con el código
original.

## B. Barreras de uso eliminadas (sin capacidades nuevas)

- **CLI de proyecto.** Añadidos `save`, `checkout`, `baseline`, `scenario`, `runs`, `evaluate` (con `--from-run`, y
  siempre imprime de dónde salen los supuestos), `compare`, `report`, `manifest`, `export` e `import`. Son envolturas
  de servicios existentes; sin ellas el flujo golden no podía hacerse por CLI.
- **Manifiesto de reproducibilidad** (`simforge project manifest`). Incluye:
  - versiones y hashes (físico, aprobación, calendarios, producción, mantenimiento);
  - semillas, horizonte, warm-up y réplicas;
  - componentes, datasets y evaluaciones económicas (con ids de fórmula).
- **Unidades visibles.** La CLI muestra `units`, `units/h`, `h`, `min` o `%` junto al valor, y el informe añade una
  columna «Unit».
- **Contexto en la UI.** Muestra versión, hash, aprobación, MISSING obligatorios, motor y estado de validación. Avisa
  cuando hay un LLM remoto activo. RUNNING / COMPLETED / FAILED en lugar de un traceback.
- **Contrato de Python.** Sólo 3.11 (`requires-python >=3.11,<3.12`, comprobado por los scripts de release); `ruff`
  añadido a `dev`.

## C. Auditorías sin hallazgos bloqueantes

| Área | Resultado |
|---|---|
| Caché | clave = hash físico (sin economics) + motor + versión + semilla + definiciones de componentes; con trace se omite |
| Aprobaciones | física ligada al hash de contenido; un cambio económico no la invalida, pero crea otra evaluación sin aprobar. La aprobación física sólo **bloquea** la ejecución de modelos generados por IA y modelos con datos importados; las versiones derivadas se ejecutan y se marcan como no aprobadas (contrato existente, sin cambios) |
| Procedencia de datasets | `provenance.data` (dataset_id, versión, content_hash, columna, decisión, ajuste, decided_by), incluida en el manifiesto |
| Experimentos | identidad, factores, semillas comunes, versión del modelo base (corregida en B2) |
| Recuperación ante fallos | los runs sólo se guardan COMPLETED y después de terminar; una escritura fallida de SQLite lanza error (sin éxito silencioso) |
| Datos locales y seguridad | sin telemetría (Streamlit con `gatherUsageStats false`); llamadas de red sólo vía el proveedor LLM opcional (`ANTHROPIC_API_KEY`); sin secretos en ficheros versionados (lo comprueba el script de release); `.env` y `workspace/` en `.gitignore` |
| Frontera LLM | el núcleo funciona sin LLM; los tests de release eliminan `ANTHROPIC_API_KEY`; la UI muestra el estado del LLM y avisa cuando el texto sale de la máquina |
| Logs | historial en el proyecto; logs de error (versión, comando, traceback) sin variables de entorno ni filas de datos |
| Botones muertos | ningún «coming soon» en la UI; todos los botones tienen etiqueta y los principales se pulsan en los smoke tests |
| Instalación limpia | venv nuevo + `pip install .[ui,data,dev]` + ejecución desde otro directorio: PASS |
| Rendimiento | línea base guardada (`performance_baseline.json`); el chequeo sólo detecta regresiones > 10× |
