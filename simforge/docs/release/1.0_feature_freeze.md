# SimForge 1.0 — Feature freeze

En vigor desde el commit `26cf484` (estado de partida de la etapa *1.0 release readiness*).

> 1.0 no es una nueva ronda de funcionalidades. Perseguimos *release readiness*: estable, reproducible, instalable,
> documentado, auditable y utilizable de punta a punta con las capacidades que ya existen.

## Qué es SimForge 1.0

Un **workbench local de simulación DES industrial**. Lleva un estudio de forma controlada por estos pasos:

**PROJECT → MODEL → VERIFY → APPROVE → RUN → EXPERIMENT → ECONOMIC EVALUATION → COMPARE → EXPORT / REPORT**

Sólo usa las capacidades de la matriz [`1.0_capability_matrix.md`](1.0_capability_matrix.md).

**No** significa ninguna de estas cosas:

- «soporta cualquier proceso industrial»;
- «validado para cualquier planta»;
- «toma decisiones automáticamente».

## Regla de admisión durante la etapa

Una petición sólo entra si cumple al menos uno de estos criterios:

- corrige un bug;
- elimina una barrera de uso;
- corrige documentación;
- corrige persistencia;
- corrige instalación.

Todo lo demás pasa a `DEFERRED_POST_1_0`. Una decisión que implique nueva semántica de dominio, una capacidad DES o
económica nueva, optimización o IA nueva **no se implementa**: se registra como `POST_1_0_CANDIDATE`.

## IN 1.0

| Ámbito | Contenido |
|---|---|
| Núcleo DES (motor 0.9.0) | fuentes, sumideros, buffers, servidores/máquinas, recursos/operarios con despacho, transporte y carriers, FIFO, prioridad, objetivo de WIP, scrap/rework por enrutado probabilístico, averías legacy |
| Distribuciones | constant, uniform, triangular, normal/lognormal, exponential, gamma, weibull, empírica, truncamiento explícito, `work_units` con agregación declarada |
| Datos medidos | importar CSV/XLSX → validar → estadística → ajuste (7 familias) → decisión del ingeniero → aplicar con procedencia |
| Calendarios (0.6) | turnos, descansos, excepciones, FINISH_CURRENT / PAUSE_RESUME / STOP_RESTART |
| Productos y setups (0.7) | mix probabilístico / secuencia explícita, tiempos y rutas por producto, setups constantes / por destino / matriz |
| Mantenimiento (0.8) | reloj ELAPSED / OPERATING, reparación correctiva con recursos, PM por calendario / uso, RESET / NO_RESET |
| Economics (0.9) | valoración post-run, cobertura, anualización explícita, CAPEX, comparación (deltas, ahorro, payback simple, retorno) |
| Experimentos | rejilla de factores con números aleatorios comunes |
| Proyecto | versiones inmutables, aprobación física y económica, historial, export/import `.simproject`, informe, manifiesto de reproducibilidad |
| Interfaces | CLI (`simforge …`) y UI local (Streamlit) |
| Validación real | protocolos de calendarios y de economics, listos (READY) |

## OUT OF 1.0 (nunca prometido en 1.0)

- 3D, gemelo digital en tiempo real, MES/ERP, cloud, multiusuario, simulación distribuida.
- Optimización o búsqueda automática; ranking o recomendación automática.
- Análisis o informes generados por IA.
- Mantenimiento predictivo.
- NPV/IRR, FX, impuestos, amortización, financiación, reparto de costes compartidos.
- Nuevas reglas de despacho; nueva semántica de setups, de mantenimiento o de calendarios.
- PDF o PowerPoint nativos (el informe es HTML, imprimible a PDF desde el navegador).

## DEFERRED (POST_1_0)

| Item | Motivo |
|---|---|
| Estado `RUNNING/FAILED` persistido como fila en `runs` | 1.0 guarda sólo runs COMPLETED; los fallos e interrupciones van al historial (`run_failed`, `run_interrupted`). Una tabla de estados exige migración y UX nuevas |
| CI en GitHub Actions | la puerta de release es `scripts/release/check_release.py`, ejecutable en local |
| Ejecutar el protocolo de validación desde una instalación sin checkout | `validate-real` necesita el checkout del código (herramienta de validación) |
| Detección de datos personales más completa | el validador económico sólo detecta correos y cuentas bancarias |
| Barra de progreso porcentual | el motor no conoce de antemano el número de eventos; se muestra el estado (RUNNING / COMPLETED / FAILED) |
| Incertidumbre económica entre periodos reales | fuera del protocolo económico 1.0 |
| Importador XLSX de plantillas de validación | las plantillas son CSV |

## EXPERIMENTAL (incluido, no forma parte del contrato de 1.0)

- **Asistente IA** (descripción en lenguaje natural → modelo; LLM remoto opcional). Funciona sin conexión con un
  intérprete por reglas. Su salida **siempre** requiere aprobación del ingeniero. El benchmark semántico está
  congelado (FREEZE).
- **Benchmark contra AnyLogic** (soldadura selectiva): BLOCKED hasta recibir los datos de referencia.

## Estado de validación (resumen; el detalle está en la matriz)

| Etiqueta | Capacidades |
|---|---|
| VALIDATED (software) | flujo completo cubierto por la suite automatizada (706 tests en esta etapa), workflow golden, regresión 01–05 exacta |
| SYNTHETICALLY_VALIDATED | todas las capacidades de dominio (DES, distribuciones, datos, calendarios, productos y setups, mantenimiento, economics) |

La madurez del software (`SOFTWARE_RELEASE_READY`) es independiente de la madurez de validación industrial: ninguna
etiqueta de este documento afirma validación industrial.
